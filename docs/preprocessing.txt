  Project Purpose

  This directory implements an Argoverse 2-style preprocessing pipeline for motion forecasting. It
  converts raw per-scenario folders containing trajectory parquet files and map JSON files into focal-
  agent-centric, normalized, filtered, sharded PyTorch datasets.

  The core output is a list of scenario dictionaries saved as shard_XXXXX.pt, plus a manifest.pt. Each
  scenario stores agent history, focal future, local map features, masks, and the raw anchor pose.

  End-To-End Pipeline

  1. refinery.py scans raw_root/train and raw_root/val.
  2. Each scenario directory is expected to contain one .parquet and one .json.
  3. The parquet is converted to agent history and focal future tensors.
  4. The JSON map is converted into lane-centerline point features.
  5. transform_scene moves all geometry into the focal agent’s local frame at history timestep 49.
  6. apply_triple_sieve filters map points and agents.
  7. Processed examples are stored in shards of 1200 scenarios.
  8. A manifest records (shard_filename, number_of_examples).

  Input Schema

  Expected parquet columns:
  focal_track_id, track_id, timestep, position_x, position_y, heading, velocity_x, velocity_y.

  Expected map JSON structure:
  lane_segments, where each lane may contain:
  centerline, lane_type, and is_intersection.

  The history horizon is fixed at 50 steps, indexed 0..49. The future horizon is fixed at 60 steps,
  indexed from raw timesteps 50..109.

  Output Schema

  Each processed scenario dictionary contains:

  - scenario_id: scenario folder name.
  - feat: shape [A, 50, 5], float16; normalized agent history as (x, y, heading, vx, vy).
  - history_mask: shape [A, 50], bool.
  - agent_mask: shape [A], bool.
  - map_feat: shape [M, 6], float16; normalized map points as (x, y, cos_heading, sin_heading, type_id,
    is_intersection).
  - map_mask: shape [M], bool, all true after filtering.
  - future: shape [60, 2], float16; normalized focal future positions.
  - anchor: shape [3], float16; raw focal (x, y, heading) at timestep 49.

  Coordinate Normalization

  Let the focal agent at timestep 49 be the anchor:

  a = (x_f,49, y_f,49)
  theta = h_f,49

  The code uses the rotation matrix:

  R(-theta) = [[ cos(theta),  sin(theta)],
               [-sin(theta),  cos(theta)]]

  For any position p:

  p_rel = R(-theta) (p - a) / 50

  For any velocity v:

  v_rel = R(-theta) v / 50

  For any agent heading h:

  h_rel = h - theta

  For map direction vectors, the raw direction is computed from adjacent centerline points:

  dx = x_next - x
  dy = y_next - y
  mag = sqrt(dx^2 + dy^2)
  cos_phi = dx / mag
  sin_phi = dy / mag
  phi = atan2(sin_phi, cos_phi)

  Then map orientation is stored as:

  cos(phi - theta), sin(phi - theta)

  Future positions are transformed with the same position equation:

  future_rel = R(-theta) (future - a) / 50

  So the preprocessing creates a focal-centric local coordinate frame where one normalized unit
  corresponds to 50 meters.

  Map Encoding

  Map features are lane-centerline vertex features only. Each centerline point becomes:

  [x, y, cos_heading, sin_heading, lane_type_id, is_intersection]

  Lane type IDs are:

  VEHICLE    -> 1
  BIKE       -> 2
  BUS        -> 3
  PEDESTRIAN -> 4
  unknown    -> 0

  No lane connectivity, lane boundaries, traffic lights, stop signs, drivable polygons, speed limits, or
  topology edges are encoded in this directory.

  Triple Sieve

  The filter in sieve.py has three parts.

  Map sieve:

  keep map point m iff ||m_xy|| <= radius / 50

  With default radius = 50 m, this keeps map points within normalized radius 1.0. If no map point
  survives, the nearest map point is kept.

  Agent distance is computed in normalized space and converted back to meters:

  d_i,t = 50 ||p_i,t - p_f,t||

  Invalid history timesteps are assigned distance 1e6.

  Agent keep rule:

  keep_i = min_t d_i,t <= 50

  Top-K fallback at final history step:

  topk_i = i belongs to K nearest agents at t = 49

  Default K = 9.

  Final agent mask:

  final_i = keep_i OR topk_i OR (i == focal_idx)

  Dropped agents are zeroed, but the tensor shape remains [A, 50, 5]. The pipeline does not compact
  agents; consumers must use agent_mask and history_mask.

  Graph Builder

  graph_builder.py is a separate utility. It is not called inside refinery.py.

  It defines flattened node IDs:

  node_id(b, a, t) = b * (A * T) + a * T + t

  It can build:

  - temporal edges: same agent from t to t+1;
  - spatial edges: same timestep, top-k nearest neighboring agents;
  - cross edges: source timestep t_s to future timestep t_d.

  Distance edge rule:

  keep edge iff ||p_src - p_dst||^2 <= rad^2

  Invalid edges are not removed; they are redirected to a sink index:

  sink = B * A * T

  Important: because trajectory preprocessing scales positions by 1/50, graph radii must be chosen
  consistently. A physical 30 m graph radius would correspond to 0.6 in normalized coordinates.

  Paper-Ready Description

  A defensible preprocessing paragraph would be:

  For each Argoverse-style scenario, we construct a focal-agent-centric representation using the focal
  agent pose at the final observed timestep. We use 50 observed timesteps and 60 future timesteps. All
  agent positions, velocities, focal future positions, and lane-centerline map points are translated by
  the focal position at timestep 49, rotated by the negative focal heading, and scaled by 50 m. Agent
  histories are represented by five channels: normalized x-position, normalized y-position, relative
  heading, normalized x-velocity, and normalized y-velocity. Map features are extracted from lane
  centerline vertices and represented by normalized position, relative lane direction encoded as cosine
  and sine, lane type, and an intersection indicator.

  To reduce irrelevant context, we apply a local filtering procedure. Map points are retained if they lie
  within 50 m of the focal anchor after inverse scaling, with a nearest-point fallback when no point
  satisfies the radius. Agents are retained if they are ever within 50 m of the focal agent during the
  observed history, or if they are among the 9 nearest agents at the final observed timestep; the focal
  agent is always retained. The resulting examples are stored as mixed-precision PyTorch shards
  containing normalized histories, masks, local map features, normalized focal futures, and raw anchor
  metadata.

  Important Caveats

  The code assumes the focal agent has a valid state at timestep 49; there is no explicit validation.

  There is no future_mask. Missing focal future values would remain zero before transformation and become
  artificial relative coordinates.

  Invalid history timesteps for kept agents must be masked downstream. Transformation happens before
  sieving, so padded zero world coordinates can become nonzero local coordinates.

  Headings are subtracted but not wrapped to [-pi, pi].

  The graph builder is available but not part of the shard-generation path.

  Rerunning preprocessing does not clear old shard files, so stale shard_*.pt files can remain and enter
  the manifest.

  The implementation is compact and research-usable, but for a NeurIPS paper you should avoid claiming
  richer map semantics or graph preprocessing unless those are added or performed elsewhere.
